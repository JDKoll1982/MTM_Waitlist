MTM Waitlist Application

Released October 29, 2026

Version 1.1.1

Highlights

  • The application now updates through the MTM Loader, which replaces it safely and keeps one previous copy in case the new one will not start.
  • Nothing you do changes. Every screen, every request and every save works exactly as it did in the previous version.
  • This release is groundwork: the screens for the generic request flow now exist, so they can be reviewed before any database work is written.

No action is needed. If the MTM Loader offers you version 1.1.1, take it. Requests you have already raised are untouched.

What changed

Updates arrive through the MTM Loader

The application is now published in the form the MTM Loader delivers, with a file list it checks before it switches you to a new version. The Loader copies the new version to your machine, verifies every file, and only then makes it the one you run. If the new version does not start, the previous one is still there.

Groundwork for the generic request flow

New screens have been built for a generic request: choosing a work center, category and item, stating the part with its stage and sequence, choosing dunnage, stating a scrap type, searching for a die, giving a needed-by time, reviewing, and seeing the result. In this release they are not part of the application you run. They are being reviewed first, so the layout and the wording are settled before any of the data work is written.

Behind the scenes

  • The screens are built so the same layouts will work when their real data arrives, without being rewritten.
  • Every piece of that temporary material is named so one search finds all of it, and a check now fails the build if any of it is reachable from the application you run.

Why it matters

Two things come out of this release. The next version of the generic request flow will be laid out and agreed before it is connected to the plant systems, which is cheaper than changing a screen that is already saving data. And from this version on, the application reaches a floor machine the same way the other MTM applications do: through the Loader, verified, with a way back.

Action you need to take

None. The application keeps its settings, its saved requests and its pictures. There is no database step, no reconfiguration and no sign-in change.
